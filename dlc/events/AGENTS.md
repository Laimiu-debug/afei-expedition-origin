# 事件 DLC 的长期规则

用户于 2026-09-30 明确要求：后续提供的事件加入本 DLC，确保与主 Mod 和其他 DLC 不冲突，并避免触发循环依赖检测或恶性触发循环。

- 默认新增内容放入 `dlc/events`，主要为路上或酒馆暗雷事件。具体剧情、人物、选择和结果以用户后续要求为准，不自行补造正式剧情。
- 保持独立 ZIP、Mod ID、文件路径、类名及 `afeix_dlc_events_` 存档标记；不得覆盖主包或兄弟 DLC 文件，不得复用其他包的事件、物品、技能、背景 ID。
- 加载依赖默认只有主包，方向为主包先加载、事件 DLC 后加载。主包不得反向依赖本 DLC，兄弟 DLC 不得互相要求先后加载。确需可选联动时，使用存在性检查和独立兼容入口，并验证完整依赖图无自环和闭环。
- 内容模块不得循环 include。Hooks 只安装一次，调用预先捕获的原函数，禁止通过已替换的同名函数回调自身。不得停用或绕过 Hooks 的循环检测器。
- `condition`、`canChoose`、评分和候选筛选必须只读，不发奖、不扣资源、不改冷却、不排队或触发另一个事件，也不递归调用候选池或结算。选项结果统一经 `apply` 结算，失败不得每帧或无上限重试。
- 事件必须有退出路径；使用正数的共享／单事件冷却和酒馆尝试间隔。保留一次性完成记录、当前事件互斥、重复结算与过期回调保护，不在事件关闭时立即再次打开自身。
- 尊重原版及主包的活动事件、筛选线程、战斗／加载／菜单状态；事件结束必须返回原先地图或酒馆，不清空其他包的状态。保持原版事件存档格式，新增存档类时重新审查兼容边界。
- 每次新增或更新事件必须运行 `python dlc/events/build.py`，检查主包及全部本仓库 DLC 的路径和 ID 冲突、加载顺序和内容 include。加入该事件的前置、所有选项、资源不足、参与者离队／死亡、重复点击、异常回调、冷却、存读档回归。
- 在实际游戏中验收主包单独搭配本 DLC，以及与希文／里根儿、阿飞语音等当前可选 DLC 同装的启动、事件触发和关闭。离线通过与实机通过分别记录；外部未知 Mod 不得宣称已经兼容。
- 保留当前工作区其他任务修改。没有用户要求时，不自动安装、发布网站、提交或推送。
