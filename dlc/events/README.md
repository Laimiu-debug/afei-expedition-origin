# 旅途与酒馆 · 独立事件 DLC

按用户要求于 2026-09-30 新建，后续用于添加**路上或酒馆里随机触发的暗雷事件**。独立 Mod ID：`mod_afeix_dlc_events`；独立目录和 ZIP，依赖阿飞远征团 **v0.28.4（内部版本 54）或更新版**及 Legacy Modding Script Hooks。

**0.1.0 是空事件框架：正式事件数为 0，目前不会弹出新增剧情。** 没有把占位文案或测试剧情放进游戏，也没有搬迁主包现有事件。已有主包和其他 DLC 的源码、版本、安装与网站发布状态不由本框架修改。

本轮通过 **129 条事件离线断言、7 项冲突检查回归、3 项本机 Hooks 队列验证、5 份运行脚本和 1 份模板编译**，独立 ZIP 的完整条目、CRC 和源码字节核验通过。未启动游戏，尚未实机验收。

## 触发方式

| 场景 | 入口 | 当前默认规则 |
| --- | --- | --- |
| 路上 `road` | 行军时参加原版随机事件池 | 原版决定检查时机；按事件权重筛选，不保证某天必出 |
| 酒馆 `tavern` | 打开酒馆后，接入主包已有的延迟遭遇入口 | 存在合格事件才抽签；默认 25% 命中；未命中继续主包酒馆流程 |
| 两处 `either` | 以上两种入口 | 同一个事件身份、完成记录和冷却 |

只作用于阿飞远征团起源。战斗、战斗切换、加载画面、危险环境和不合适的菜单状态会阻止触发；酒馆还检查城镇身份、当前酒馆对话、角色界面、事件界面和正在进行的原版事件筛选。原版喝酒、传闻和事件结束后返回酒馆的流程沿用原有入口；命中 DLC 时仍登记主包的酒馆访问进度。

每次成功显示剧情后默认让本 DLC 全部事件冷却 **1.5 游戏日**，同一剧情冷却 **8 游戏日**。默认第 **3 日**起可触发；可以逐个事件更改。关闭未完成的谈话也会消耗显示冷却，防止反复刷同一幕。酒馆存在合格事件并进行过抽签后，全部城镇共用 **1 游戏日**的尝试间隔；未命中也保留记录，重复点击或换城不重新抽签。空池或界面不适合时不消耗抽签。

以上是框架初始值，后续随事件设计调整，不代表已经确认的剧情数值。

## 后续添加事件

后续开发必须遵守本目录的 [长期开发规则](AGENTS.md)。每次实装都会检查主包、希文／里根儿、阿飞语音以及当时其他本仓库 DLC 的路径、Mod ID、运行类 ID 和完整加载依赖；循环 include、循环依赖、前置判断递归和重复结算均为阻止打包的问题，不绕过 Hooks 检测。

1. 将 [事件模板](templates/event.nut) 复制到 `src/scripts/mods/afeix_dlc_events/`，例如 `lost_purse.nut`。
2. 修改 `id`、`title`、`text`，选择 `road`、`tavern` 或 `either`，填写 1～4 个选项及各自结果。每幕还会提供“结束谈话”，保证能返回游戏。
3. 设置触发前置：`minDay`、`members`（稳定角色 ID）、可选 `condition`；设置 `weight`、`cooldownDays` 和 `once`。一次性事件在成功选择后登记完成，单纯关闭不会完成。
4. 将文件名加入 [内容入口](src/scripts/mods/afeix_dlc_events/content.nut) 的列表，例如 `foreach (part in ["lost_purse"]) ...`。没有登记的文件不会执行。
5. 执行检查、再打包。每个实际剧情还需要针对自身资源变化和前置条件增加回归，并在游戏中验收。

事件 ID 只能使用小写英文字母、数字和下划线，长度不超过 48。登记后保持稳定，不把旧 ID 改用于另一篇故事。模板、测试与原版夹具均不进入运行 ZIP；测试剧情只存在于隔离测试环境。

选项的 `canChoose(event)` 先验证资金、背包和其他条件，`apply(event)` 执行结果。**多个资源变化必须先全部验证，再统一处理，必要时自行回滚**；框架不自动回滚作者写的任意回调。结算会再检查当事人，防止过期事件或重复点击重复扣钱／发奖；回调报错后会停止该次结算并提供退出结果，不能通过重复点击再次执行。冷却与完成记录使用独立的 `afeix_dlc_events_` 存档标记。

后续提供事件构想时，可直接写：**在哪里遇到、哪些人要在队里、发生什么、有哪些选择、各自结果、是否只出现一次**。未指定的触发权重和数值可在实装时一起确定。

## 检查、打包与试玩

仓库根目录执行：

```powershell
python dlc/events/build.py --check
python dlc/events/build.py
```

检查器从本机原版游戏包临时读取事件、事件管理器、酒馆点击和世界事件界面代码，编译本 DLC 脚本，验证原版事件筛选、选项、酒馆返回、冷却、前置、重复结算与原版事件存读格式。临时夹具位于忽略的 `.cache`，检查器只读取主包源码并验证其字节未变化。它检查与主包及本仓库其他可选 DLC 的大小写路径冲突、Mod／运行类 ID 冲突和加载顺序闭环，并直接执行本机已安装 Hooks 的队列排序代码，验证正常组合通过、自依赖和互相依赖被拒绝。内容登记使用 include 重入检测，外部进程设有超时，检查挂起不能继续打包。

前置判断抛异常或递归调用候选池时，该事件会在本次会话内停止参与筛选，避免每帧反复报错或杀死原版筛选线程；修正后重启游戏可重新检查。选项判断也受结算重入保护。开发者仍须保持这些判断只读，并按 `AGENTS.md` 完成实际游戏组合验收；当前检查不代表任意第三方 Mod 都已验证兼容。

输出：

- [独立 ZIP](<dist/mod_afeix_dlc_events v0.1.0.zip>)
- [SHA-256 校验值](<dist/mod_afeix_dlc_events v0.1.0.sha256>)
- [构建与验证报告](report.json)

框架可以打出空包，用于准备目录和加载入口；**安装空框架不会新增剧情**。有具体事件后，退出游戏，把主包、本 DLC ZIP 一起放入游戏 `data` 目录，保持 ZIP 原样，并让每个 Mod 只保留一个版本。按项目约定使用新战役验收，不承诺旧战役升级兼容；本框架尚未自动安装、提交、推送或发布网站。

离线验证不能替代实机验收。后续实际剧情要检查随机出现、酒馆叠层／返回、各选项、资源变化、参与角色离队或死亡、存读档以及与其他 DLC 同装。当前保留原版事件的序列化格式，没有新增物品、背景或技能类；未来事件若新增这些内容，卸载和存档兼容边界需要重新确认。
