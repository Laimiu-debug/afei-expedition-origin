# v0.23.1：三人同时招募、一天补位与属性显示 Mod 兼容

内部版本 27，存档 Schema 仍为 8；招募使用独立的一次性迁移标记。v0.23.0 为内部版本 26。

v0.23.1 的进一步排查直接读取了本机自动存档：参战 2 次、到访 2 个聚落、非送信契约 3 份，白小帅子、李李超欧、小酒瓶、小鱼贝壳已按此顺序排队，但不存在已生成候选人的记录。随后确认 `mod_fox_043.zip` 中的 `mod_sr_alternative_standard.nut` 在创建招募模块时整段替换 `queryHireInformation`，覆盖了本 Mod 原先注册的候选人生成回调。问题不在解锁条件或关系门槛。

现在还在原版城镇屏幕 `showHireDialog` 入口准备人物，再交给现有 Mod 的查询和属性转换函数显示。入口通过 `mods_hookNewObject` 注册，以匹配 `world_town_screen` 的原版裸表结构；进入聚落时的准备逻辑仍保留。无需卸载属性显示 Mod，也不需要修改原存档。使用本机该 Mod 原脚本复现了“四人排队、零候选”，并验证修复后的三人显示、原队列顺序、真实第三方雇佣包装回调、一天补位和跨村转移。测试的单个人物画面转换由替身提供，实际游戏画面尚待确认。存档与冲突证据保存在 `build/recruitment-v23/compat-diagnosis.json`。

在阿飞起源的非敌对、非军事聚落打开原版招募界面，最多同时出现 3 位已达标主题人物，与普通佣兵并列。普通中立村庄也可以；集市的装备、粮食交易列表不显示人物。代码中的 `isAlliedWithPlayer` 不要求刷高好感：原版默认关系为 50，低于 20 或临时敌对才排除。各人的解锁条件保留，单纯经过几天不会解锁角色：最早的小酒瓶需要参战一次，白小帅子需要实际进入两座不同的合格聚落。

修正原版佣兵池为空时的入口循环依赖：原版人群建筑在没有候选人时隐藏，而旧代码仅在查询招募界面时生成主题人物。现在进入聚落、原版刷新结束后即准备候选人，使白天的人群入口能显示。夜间仍按原版隐藏人群，可等天亮后进入。

三个位置分别计时。招走一人，该位置在一个完整游戏日后补入最早排队的人；其他候选人仍可立即招募。未使用的位置在有人达标时立即填充。每位候选人保留四天，错过后排到队尾；换聚落转移现有候选人，不重抽、不刷新有效期。原版的资金、名册容量检查继续负责扣款和人员转移。

旧存档把原有候选人迁入第一个位置，保留原实体、装备和有效期，另开放两个位置。旧三天雇佣冷却按原雇佣时间缩短为一天，超过一天的等待不会重新开始。三个位置的身份、所在聚落、到期和补位时间均通过世界标记存档，重复加载不会再迁移。

原版非送信契约保留；本机游戏日志记录过护送商队、猎杀野兽、清剿墓地、驱逐强盗等实际生成。本轮另修正额外送信占用普通契约容量并重置供给时间的问题：普通村庄和南方城邦的原版供给判断仅排除 Mod 送信，生成此送信时保留雇主原有供给时刻，任务本身仍正常登记、显示和保存。原版送信仍占原版容量，其余契约仍按原版供给冷却，不保证每个聚落随时有任务。旧档此前被送信推进的供给时间无法可靠还原，可能还需等当前冷却自然结束一次。

检查范围包括原版招募模块下的同时三人、各自一天的精确边界、错峰雇佣不互相延长等待、跨村转移、原版刷新保护、四天轮换、缺钱／满员／创建失败、全部 31 人逐步雇佣，以及旧单人存档迁移。另用原版人群建筑验证空池入口、用原版派系和契约管理器验证非送信容量／计时，以及中立关系准入。完整游戏中的真实序列化和界面显示仍需试玩确认。

安装前原包保存在 `build/recruitment-v23/baseline-*/`；构建与安装校验见 `build/gameplay-validation.json`、`build/gameplay-package.json` 和 `build/recruitment-v23/installed.json`。重启游戏后可读取原存档。2026-09-28 按用户要求将 v0.23.1 发布至 BBMOD，介绍、兼容说明和下载包同步更新，公开下载与本机包一致，详见[网站发布记录](releases/publication-0.23.1.md)。
