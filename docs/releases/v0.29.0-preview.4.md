# v0.29.0-preview.4：修复梦境无法进入

2026-10-03，本地修复版，内部版本68。完整主Mod包。

新开局点击“走进这场梦”以及F8“再赴梦潮”继续序章时，梦境创建或战场加载失败。实机日志确认四个连续阻塞：

- 原版玩家初始化中的 `actor.setDirty` 无参数调用 `Math.rand()`；临时梦境随机函数只接受两个参数，触发 `wrong number of parameters`。现在支持无参数与双参数调用，仍不消耗战役随机序列，并在成功和异常时恢复原函数。
- 原版装备通过继承访问耐久和疲劳字段；`field in item.m` 只能看到本地字段，误报 `Unknown dream item property: Condition`。现在通过原版属性访问检查继承字段，同时保留对未知字段的拒绝。
- 梦境敌人只提供脚本、阵营等部分字段，缺少原版布阵必需的 `Row`，加载时报 `the index 'Row' does not exist`。现在按幕复制蜘蛛、恐狼、林德虫、巨魔的完整原版兵种定义，为斗鱼替换脚本，保留布阵及战斗处理需要的数据。
- 梦境采用场景模式隔离战役结算，会分配32个战术阵营槽；原版自动底座分配却按这些槽访问现有战役阵营，越界报 `the index '31' does not exist`。现在像原版竞技场一样关闭梦境自动底座分配；现实终局保持原版处理。

新增回归覆盖执行安装游戏的完整 `actor.setDirty`、四幕敌人的原版布阵与装备初始化，并模拟装备继承的 `_get/_set`。完整离线检查及实机两个入口结果见[梦境入口修复报告](../../build/dream-entry-0.29-preview.4.json)。

实机通过：原失败自动存档在安全扎营后，从F8继续序章进入第一幕；实际移动、弓箭攻击和菜单撤退梦醒正常，三人现实队伍及资源恢复。全新战役直接进入第一幕并攻击命中。最终日志没有脚本错误；45,818条离线行为断言、147个Squirrel文件及324个包文件校验通过。本机已安装，原存档已还原，完整四幕与现实终局尚未实机验收。

退出游戏后替换data目录里的主包，保留一份 `mod_afeix_expedition.zip`。卡在梦境序章的旧档可继续，不需要重开才能应用修复。
