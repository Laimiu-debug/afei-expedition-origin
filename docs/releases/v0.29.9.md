# v0.29.9：减少击杀时的重复扫描和无效刷新

2026-10-14，内部版本 87。完整主包已安装到用户 G 盘游戏，并发布到官网及 GitHub，见[发布记录](publication-0.29.9.md)。

用户报告击杀后短暂停顿。当前日志仍是上一轮菜单测试，不能用它判断新一场战斗；因此用 `autosave` 的字节一致副本加载原 21 人敌方遭遇，关闭战役保存，暂停 AI，直接执行原版 `actor.kill` 来隔离死亡处理。原版每次死亡向全场存活且已放置的角色广播 `onOtherActorDeath`。主包此前在每个接收者的回调后调用 `tryTurtleAwakening`，后者又扫描全场，造成随人数增长的重复工作。

实机基线三次击杀（阿飞、大谋、阿飞；怨魂、怨魂、行尸）分别产生 32、31、30 次觉醒检查，34、33、32 次全场扫描，人物身份读取 438、425、412 次。新版本仅由小龟接收死亡通知后执行觉醒检查，其余角色保留全部原版回调、参数与返回值。小龟仍在最后一名其他队友死亡后立即觉醒；原来的回合开始检测和参战胜利冷却记录保留。

另一个开销是 `checkMorale` 在原版直接返回的士气状态上仍先刷新技能，进而刷新人物画像。针对 Ignore、正向检定时已经 Confident、负向检定时已 Fleeing，以及普通 +1 对 Fleeing 的四种原版提前返回条件，跳过额外光环刷新，继续完整调用原版检定。不修改 `getBravery`，真正需要检定时仍先刷新光环，保留 v0.29.7 的怨魂线程 AI 修复。

回归覆盖 32 个接收者连续两次死亡广播的单次扫描、全部原版参数与返回值、最后队友死亡立即觉醒、四类提前返回状态、逃跑角色的 +2 鼓舞和真正士气检定。151 份 Squirrel、47,065 条行为断言、游戏资源路径与 JavaScript 检查通过。完整 ZIP 的 332 个条目、CRC 和源码字节检查通过。

实际引擎相同副本复测，每次觉醒检查均为 1 次，全场扫描均为 3 次（包含原版处理），人物身份读取降为 74、73、72 次。三次击杀至下一次战术更新的帧间隔由 87.19 / 50.95 / 46.35 毫秒降为 57.85 / 47.03 / 38.58 毫秒。基线和修复测试均没有脚本或严重异常。同步调用内的原版计时不前进，所以 `native_kill_ms=0` 不能解释为击杀零耗时；帧间隔包含计数器开销、渲染、声音、调度和机器负载，三个样本不代表日常游戏中所有战斗的固定延迟，也没有进行人工鼠标攻击验收。
