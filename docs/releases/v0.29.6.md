# v0.29.6：完整头像下的行动条查询恢复

2026-10-13，内部版本 84。本地失败版，未发布到官网或 GitHub，已由 v0.29.7 替代。

**选择器恢复仅缓解表象，未解决根因。** 经用户指定的 `autosave` 副本自然复现，第 4 回合出现查询 0 个槽位而真实 DOM 有 7 个，局部恢复让战斗暂时继续。随后另一轮副本测试第 4 回合触发引擎严重异常。Squirrel 调用栈清楚显示线程怨魂 AI 的 `getBestTarget -> getBravery` 经本模组进入 `refreshMemberAura -> skills.update -> setHitpointsPct -> syncCharacterArt -> setDirty -> TurnSequenceBar.updateEntity`。v0.29.7 修复只读勇气接口中的写操作，并彻底撤回头像重建、数据缓存和选择器拦截。以下保留该版的局部验证及设计记录。

G 盘 v0.29.5 的原始游戏日志中，头像查询返回空结果时，`before=` 记录的 HTML 仍有完整的头像层、头像、占位图和选择箭头。此前去除 HTML 标签的日志解析丢失了这段证据，导致错误地重建完整节点，并进一步触发 `previous.data.isFirst` 异常。v0.29.4/5 的浏览器案例验证了人为删除节点的假设，未验证这一实际的查找不一致。

本版撤回重建和旧画像数据缓存。只处理行动条单节点上下文中有限的画像及槽位查询，用 `firstChild`/`nextSibling` 与标签、类名校验 jQuery 的返回结果；不一致时返回原有节点。画像只重新关联同层已经存在的占位图；不新建、重排或删除头像。原版更新、选择、移除和动画完成回调保持不变，梦境过期回复处理仍保留。

游戏日志出现 `AFEIX_TURNBAR_READY version=84` 证明前端加载。真正发生查询差异时限量记录 `AFEIX_TURNBAR_QUERY_FALLBACK`，含单位 ID、选择器、原生返回数量和真实节点数量；日志延后到当前查找完成之后发送，避免桥接重入。尚未确定引发原始选择器异常的最初调用方，不把局部查询恢复称为根因已完全解决。

42 条浏览器断言使用 G 盘游戏的实际 jQuery 和原版行动条代码：在完整 DOM 上注入空匹配/错误图片匹配，验证原版报错且移除未完成，再验证已有节点、数据、事件、异步缩放、移除及下一角色激活；另验证范围限制、真正缺失结构不被重建、空槽位和梦境回复。7 条 Squirrel 断言验证日志桥接。全项目检查：152 份 Squirrel 脚本、46,883 条断言，G 盘资源路径及 JavaScript 检查通过。浏览器动画与桥接仍是受控替身，游戏引擎对照结果另行记录。

临时引擎自检 ZIP 仅用于独立场景，不进入主包。测试直接使用 G 盘的 Coherent、jQuery、原版 UI 和动画，包含怨魂尖啸与士气变化。注入选择器故障属于受控对照，不等于原战役自然复现；必须区分启动、合成故障恢复和原故障战役验收。
