# 34 人专属背景与异教徒转化设计

日期：2026-09-28。范围为当前 `CharacterOrder` 中的 34 人；沿用[人物故事](character-stories.md)、[现行属性](character-stats.md)和[专属技能](member-skills.md)。v0.20.1 已将本表背景名与介绍接入游戏，并提供短工、民兵、偷猎者旧背景迁移；皈依者保留机械身份并组合个人文案。数据源为 [character-backgrounds.json](../../data/character-backgrounds.json)，[验证范围](../playtest-0.20.1.md)区分离线检查与待完成的实机验收。

## 设计原则

每人的背景回答三个问题：来到黑旗前凭什么生活、带来了什么习惯、还有什么事想完成。背景名与外号分开，例如“小酒瓶／蛤妈”的专属背景是“球场突击手”。背景不限制装备、武器和玩家配点。

下表来历均为游戏创作，承接现有故事中的场景与特点，不作为真人履历。2026-09-28 蓝队原第 17 位由小哈尼更正为罗一可，罗一可已按用户补充的仓鼠称呼重写为随行藏粮人，并与眼子一同补齐[个人剧情](blue-team-stories.md)；老蔡“地图推演”的定位也保留可调整标记。外星人、鹌鹑、太子、大王、吕布等称呼，不自动附带种族、贵族身份或超自然能力；小龟沿用已确定的男性龟形化身。

本轮背景不增加一层属性奖励。起始属性、天赋、工资与招募价格沿用现行配置；差异通过背景介绍、原有成长选择和专属技能表达，避免抵消刚完成的强度调整。

本轮按用户更正归为刀一、刀二、0.5DFW猪团与旅途来客。陈知含退出当前背景表，背景类同步移除，不保留旧档兼容。

## 转化与角色路线

设计结论：34 人均保留被原版事件转化的资格，不因具名、队长、外号或六根身份获得隐藏豁免。是否实际被选中仍遵守原版的队伍、特性、事件冷却和随机条件。本稿不新增“必定转化”按钮。

本批专属背景统一保留普通民间出身（`IsLowborn = true`、`IsNoble = false`）。会算账、画地图或主持游戏不自动加“聪明”特性；太子、大王等外号不自动加贵族标签。随机特性仍沿用现行底层模板的规则：例如原版偷猎者模板排除“聪明”，不能为了换背景名字顺便改写这一分布。确实拥有“聪明”的角色按原版规则处理，脑损伤等例外也不另行改写。

转化后的规则为：

1. **原来的经历继续存在。**角色仍是同一位阿飞、抹茶或可可。名册保留原生专属背景；当前机械背景成为原版“皈依异教徒”，供原版异教徒事件识别。
2. **个人路线继续。**不清除已经完成的成长、作出的选择、战斗次数、研习方向、阿飞转职、六根进度或自行车事件记录。不因转化重新发放奖励。
3. **信仰增加对话差异。**可以改一句营地交谈或剧情反应，不改变原有任务目标，也不强制改走坏结局。转化不直接授予异教徒起源专用的祭献晋升体系。
4. **原有条件继续生效。**要求本人存活在队的场景仍要满足该条件；已明确允许离队后推进的记忆与线索保持原规则。死亡、主动离队等后果不能由转化绕过。

人物界面的设计示例：

> 午夜抹抹茶 · 队长  
> 原生背景：随军账房  
> 当前信仰身份：皈依异教徒  
> 原有人物介绍继续显示，末尾补充：他开始在账本末页记下达库尔的祷词。算盘仍在响，黑旗欠下的账也仍要有人付清。

界面中的“原生背景”和“当前信仰身份”用于解释同一个人的经历与现状；实现时仍只有一个当前机械背景，不同时装备两份背景技能。

## 当前代码核对与实现要求

以下分清当前行为与待实现部分，不能把本稿当作已发布功能说明。

| 项目 | 当前代码依据 | 转化影响与设计要求 |
| --- | --- | --- |
| 角色身份 | `roster.nut` 的 `characterId()` 读取角色 flags 中的 `afeix_character`；`findCharacter()` 按该身份找人。 | 原版转化只替换背景技能，不删除该标记，因此仍能找到原来的角色。 |
| 首段个人成长 | `story_progress.nut` 的 `growthStatus()`、`resolveGrowth()` 使用身份、等级、参战次数与世界进度。 | 已有代码不要求短工、民兵或偷猎者背景，转化本身不会锁死成长。 |
| 阿飞转职 | `promotions.nut` 的 `promotionCheck()`、`syncPromotion()` 使用阿飞身份、等级、参战、成长与路线进度。 | 蛤蟆人、嘉豪与飞碟条件继续；转化不能代替等级、履约与六根条件。 |
| 六根与自行车 | `story_progress.nut` 的 `rootStatus()`、`bicycleStatus()` 等使用对应人物与独立进度标记。 | 转化不重置开篇、回信或选择；各分支原本的在队、离队、存活条件照旧。 |
| 专属研习 | `member_training.nut` 使用 `afeix_training_choice`、固定角色身份与等级。 | 已选技能和 11 级精通资格不因背景被替换而丢失。 |
| 原版转化 | 本机原版 `scripts/events/events/cultist_vs_uneducated_event.cnut` 的成功分支移除旧背景，加入 `converted_cultist_background`，并重建介绍和外观。 | 原有专属技能不是背景技能，不在该分支移除范围；新专属背景不能把剧情进度或独有能力存在会被替换的背景对象上。 |
| 读档文案 | `roster.nut` 的 `restoreCharacterMetadata()` 当前把角色故事重新写入现有背景的 `RawDescription`。 | 已有代码不会把机械背景改回去，但没有组合专属的转化后介绍；实现时须同时展示原来经历与皈依状态。 |

当前结论来自源码检查，尚未对“转化→推进剧情→存档→读档”做实机验收。长线故事文档中尚未实现的章节，也不能据此宣称已经可通关。

接入时采用以下约束：

- 每人分配稳定的专属背景路径与 ID，例如 `afeix_afei_background`／`background.afeix_afei`。固定角色身份继续使用原有 key，不从背景 ID 反推身份。
- 每个专属背景继承此人目前使用的原版模板，仅覆写背景名、介绍及必要的显示内容。等级、属性、天赋、工资和随机特性不在换背景时重掷；起始配置仍由现有角色创建逻辑写入。
- 剧情、研习与独有能力继续保存在角色 flags、世界 flags 和独立技能中。不得在背景的移除回调里清除这些记录。
- 转化成功后保留原版 `background.converted_cultist`，以维持原版识别；显示层再补上原生身份和相应文案。不创建无法被原版事件识别的“某某专属异教徒”机械 ID。
- 旧档只迁移仍持有该角色原始模板背景的具名成员。已经皈依者继续皈依；其他已被事件或外部 Mod 替换的背景不自动覆盖。保留经验、装备、伤势、工资倍率与已选路线。
- 原版转化会调用背景外观刷新；接入时需检查并重新同步人物胸像，尤其是小龟与阿飞。既有人像同步钩子不等于已验证该次事件完整兼容。

后续验收应覆盖：34 人新建的背景显示与现行属性一致；普通成员不受影响；阿飞转化前后完成成长并转职；可可、余初九、小龟转化后继续六根；小酒瓶转化后继续自行车分支；7 级研习与 11 级精通不丢失；未完成和已完成两种进度下保存读档都不重复领奖；头像与背景文案在转化当下和读档后均正确。
